# DAP subplan 02 — the debugger UI: panes, layout, keys, REPL

Parent: `doc/plans/2026-08-11-dap.md`; prerequisites: subplan 00 stages
C-F and subplan 01 through stage 6. Everything here is projection —
`dap_ui.c` renders the session/breakpoint tables and owns no protocol
state.

## Special buffers

`*dap-repl*`, `*dap-locals*`, `*dap-output*`, `*dap-stack*`,
`*dap-breakpoints*`, `*dap-threads*`. All written through
`buf_prepare_special_text()` / the edit gateway (which keeps `dap_ui.c`
out of the mutation-gateway census by construction), read-only,
repainted from the tables on one internal "session changed" notification
— start with a single notification point; add granularity only when a
pane measurably needs it (dap-mode's nine hooks are the cautionary
tale). Repaints are debounced (~100 ms, dape's `dape-ui-debounce-time`)
and skipped for panes not currently displayed. Two content disciplines,
not one: `*dap-output*` and `*dap-repl*` are **append-only bounded
transcripts** during a session (4 MiB default each, bytes charged when
accepted, one visible truncation marker, draining-and-dropping
continues past the cap so an adapter can never block on its pipe;
killing the buffer starts a fresh transcript with a notice — the model
keeps no second copy); stack/locals/threads/breakpoints are
**model-derived replacements**.

**Row metadata, because kg has no text properties.** "RET dispatches on
what the line is" needs a mechanism dape gets from Emacs for free. Each
pane keeps a bounded metadata vector beside its text —
`struct dap_ui_row { kind (frame/thread/breakpoint/scope/variable);
suspension_epoch; stable_id; parent; depth; navigable; }` — plus the
pane's buffer handle and content generation. RET verifies
buffer/row/generation still match before acting. Text and metadata are
replaced as one transaction (build both, swap on success; on failure
the previous pane and metadata stay intact), and no metadata ever
stores pointers into a JSON document, `erow`, variable vector or
session object — all may move before the next command. Variable
expansion identity is epoch + reference ancestry + sibling ordinal +
name, never name-path alone (duplicate names across scopes and
adapter-reported duplicates are real); best-effort across stops,
exact within one. Bounds shared with subplan 01 stage 6: 256 threads,
200 frames, 64 scopes, 4096 variable nodes, depth 32, cycle marker on
repeated references, displayed name/value/type lengths capped with an
ellipsis, and a visible "N omitted" row wherever a kg limit truncated
an adapter response. Variables are fetched only for visible/expanded
scopes; a late expansion reply is accepted only if epoch, selection
generation and the still-expanded parent all agree.

Pane content rules already forced by measurement:

- `*dap-output*`: `stdout`/`stderr` categories, appended **as
  bytes-with-length** (debugpy splits one print mid-line across two
  events; JSON strings may embed NUL; event boundaries are not line
  boundaries), CR/CRLF normalization kept as *streaming state* — an
  event ending in CR followed by one starting with LF is one newline —
  arrival order preserved across categories, rendered like any buffer
  text: adapter output is untrusted and reaches the screen only through
  `display_glyph_at()` (tests include ESC, C1 bytes, invalid UTF-8,
  embedded NUL, split CRLF, and a line longer than the transport's
  stderr chunk). `telemetry` dropped before it costs budget; `console`
  goes to the REPL; stderr is prefixed/styled without inserting ANSI.
- `*dap-stack*`: rendered from the fetched frames (one on stop, 20 when
  this pane paints); frames without an openable source render dimmed and
  non-navigable; the selected frame is marked, hollow-style when it is
  not the top frame (dape's arrow discipline).
- `*dap-locals*`: scopes + variables of the selected frame only;
  expansion state keyed by name-path so it survives re-fetch across
  steps (dape.el:4616-4627). `hover`-context evaluate for values, never
  `repl` (lldb-dap formats those differently, with `$N` side effects).
- `*dap-breakpoints*` and `*dap-threads*` share one logical slot in the
  layout, as GDB does — with an explicit
  `dap-info-toggle-breakpoints-threads` command (bound in the pane) so
  the hidden one is reachable.

One shared `dap-info` major map for all panes: RET dispatches on the
row-metadata kind (frame → select+visit, thread → select, breakpoint →
visit, variable → expand/collapse) rather than one map per pane — also
thrifty with the keymap table. `d` deletes a breakpoint, `D` toggles
enable, `q` buries. Activation is by buffer *name* through one
predicate table listing all six panes — created at startup and
deactivated (subplan 01 stage 1), activated per current buffer by
`kbd.c`'s name-keyed rule; a bare `keymap_set_active()` at pane
creation would leave it active when the user switches buffers, and the
read-only-buffer predicate leak the LSP plan fixed
(`key_update_mode_maps()`) must not re-appear.

## Layout

Target arrangement (Emacs gdb-many-windows', adapted):

```
+---------------------------+---------------------------+
| *dap-repl*                | *dap-locals*              |
+---------------------------+---------------------------+
| source                    | *dap-output*              |
+---------------------------+---------------------------+
| *dap-stack*               | *dap-breakpoints*/threads |
+---------------------------+---------------------------+
```

Built in one `win_arrange_grid()` call (subplan 00-E) — never six
chained `win_display_buffer_other_window()` calls — which validates
pane handles, window count and minimum geometry *before* mutating and
returns a status F12 reports (a too-small terminal refuses cleanly,
keeping the current layout). Equal column widths are the accepted v1
limitation; a weighted reflow is a recorded follow-on.

Snapshot ownership is explicit: the first F12 in a session saves the
user's configuration exactly once and enters the grid; the second F12
restores and invalidates that snapshot; a *later* F12 saves the
then-current layout rather than resurrecting the first one. Session end
restores only when the grid is active. If the user manually
splits/deletes windows while the grid is active, session-end
restoration still returns to the pre-grid layout and discards those
changes — documented, and revisited only if it annoys in practice. (The
*preference* — auto-showing the grid — is per-session; the *snapshot*
dies on every restore. The review caught the old sentence conflating
the two.) Tests: session death with the grid active / after toggle-off
/ after a saved buffer died; terminal resize between save and restore;
restoration deferring while a prompt is open; a failed F12 on a small
terminal.

Source-line behavior on stop: visit the frame's file (the existing
shared `editor_visit_file_position()` seam the LSP xref work extracted;
its column argument is a **1-based byte column, so pass 1**, not 0 —
DAP columns are ignored in v1 per the coordinates row),
`KG_DECOR_FACE_DEBUG_CURRENT` on the stopped line. Never steal the
selected window when the user is in a `*dap-*` pane or when the stop
carries `preserveFocusHint` — the source buffer may still open in a
non-selected slot and the decoration still updates; with no source slot
available, do not replace the pane the user is reading. Decoration
priorities are defined, not incidental: current-line beats breakpoint
on the same row, verified beats pending; an empty line still gets a
defined nonempty range; decorations rebuild on buffer open, marker
move, breakpoint sync, stop, continue and session death. Faces and
ranges are asserted in *native* tests (on a row with a tab and
multibyte text) — the PTY harness observes text, not attributes.

## Keybindings

Two minor maps (both created deactivated at startup, subplan 01
stage 1), because the milestone's own first step — F9 *before*
`dap-debug` — cannot work with a session-only map:

- `dap-breakpoint`: `F9` (toggle) and `C-F9` (temporary), active
  whenever DAP is built and the current buffer visits a file. Its
  handlers work with no session (table-only, synced on the next
  session) and refuse non-file buffers with a clear message.
- `dap`: everything else, active exactly while a session exists — so
  F4-F8 and F10-F12 never shadow users outside one.

`dap-debug` stays reachable through M-x regardless of any map. Tests:
F9 before a session, after disconnect, in a generated special buffer,
and in a buffer whose file does not exist. Default table (parent plan,
decision 1 — gud-style):

```
F4    dap-evaluate            C-F5   dap-step-instruction (cap-gated)
F5    dap-step-in             F6     dap-next
F7    dap-step-out            F8     dap-continue
F9    dap-breakpoint-toggle   C-F9   dap-breakpoint-temporary
F10   dap-until               M-F10  dap-goto (cap-gated)
F11   dap-restart             M-F11  dap-terminate
F12   dap-many-windows        M-up / M-down   dap-frame-up / -down
PageUp/PageDown also frame-up/-down while a session is live.
```

The multi-request commands' algorithms (`dap-until`'s
verified-temporary-breakpoint-then-continue, `dap-goto`'s
gotoTargets→choose→goto, `dap-restart`'s adapter-request-else-relaunch)
live in subplan 01, not in UI handlers; every one that cannot run says
why ("lldb-dap does not support goto").

Every capability-gated command that cannot run says *why* ("lldb-dap
does not support goto") — never a silent approximation.

Customization story, documented in README + doc/lisp-api.md: the map
pre-exists in C, so `(define-key 'dap-mode-map "<f5>" 'dap-step-in)`
works from init.el once subplan 00-C lands; `keymap_find()`'s
`-mode-map` aliasing already resolves the name. `global-set-key` stays
C-c-only by design — F-keys are reachable through define-key precisely
because the dap map is a real native map.

Documentation path: all keys and commands in `doc/kg.1` and README.
`src/help.c` is *not* extended unless `utils/check_help_drift.py` is
taught to read the dap map's bindings in the same commit — the script
currently requires help-table keys to be bound in kbd.c's tables and
would fail otherwise.

## REPL

A prompt line *inside* the buffer would need an editable-tail mode kg
does not have (cursor confinement, undo policy, async insertion before
the prompt) — not a small v1, as the review pointed out. Instead the
input is the **minibuffer** and `*dap-repl*` is a read-only transcript:
`dap-repl` (or RET in the pane) prompts via
`editor_read_line_with_history()`, appends `DAP> expression`, sends
`evaluate` with `context:"repl"` against the selected frame while
stopped, and appends the result or error when the guarded callback
returns; history rides the normal minibuffer ring; nothing selects
windows or mutates source while the prompt is open. Replies can finish
out of order: each is prefixed with its expression and tagged with
suspension epoch + frame selection, and a stale one is silently
discarded (debug log only) rather than overwriting a newer value.
`console`-category output lands here. F4 `dap-evaluate` uses its own
prompt/history with `context:"hover"`, shows a concise echo-area
result. Completions (`supportsCompletionsRequest`) and variable
commands are follow-ons. A failed evaluate prints in place; it is never
a session error.

## PTY acceptance

The PTY harness observes plain screen text — colors are not assertable
there, so faces stay in native tests and PTY cases assert *observable*
outcomes: F9 before a session populates `*dap-breakpoints*` when
opened; `dap-debug` reaches the fake adapter's stop; point sits on the
expected file/line and the status line names the stop reason;
`*dap-stack*` shows a known frame name and `*dap-locals*` a known
variable=value (`expected_screen_contains`); F6 stops at a later line
(assert point/line, not color); F12 shows all expected pane titles at
sufficient dimensions; F12 again restores a deliberately asymmetric
prior layout; disconnect restores the layout and a debugger key then
reports no session; output containing escape/control bytes renders
visibly and never changes terminal state. Settle floors sized for the
sanitizer lanes; the fake adapter drives all of these, real-adapter
smoke stays in subplan 01 stage 7. Native tests additionally cover row
metadata dispatch, duplicate variable names, the expansion race,
transcript cap/truncation, split CRLF, prompt deferral, decoration
priorities and layout-transaction failure.
