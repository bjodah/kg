# Elisp phases 13–19: the nelisp-guided wave

Status: ACCEPTED 2026-08-10 (user), branch `more-elisp` (kg) / `more-elisp` (fe).
Phases execute sequentially, each by one delegated agent, each closed by a
full parallel CI run and a report back before the next begins.

## Provenance

Two research passes on 2026-08-10:

1. **A measured gap map of fe + kg's Lisp layer.** Every present/missing
   claim below was established by running `fe/fe` and `test/kgbatch`
   (`fboundp` / evaluation), not by reading docs. Where this plan says
   "measured", that is what it means.
2. **A mining pass over `/opt/nelisp`** (an independent self-hosted Emacs
   Lisp VM, v0.6.0). We are not copying its architecture (no JIT, no
   bytecode — kg declined bytecode with measurements on 2026-08-07 and
   nothing here reopens that). We mined it for *which elisp semantics
   matter, in what order, and what silently breaks real packages*. Its two
   most useful artifacts:
   - A mechanical audit finding that real Lisp code reaches **118 of
     Emacs' 5,646 C primitives (2.1%)**, ~90% of them special forms plus
     pure data ops. fe already has essentially all of the irreducible
     special-form core. The top unclaimed names by measured reference
     count: `signal` (#5 overall), `nth`, `aref`, `plist-get`, `intern`.
   - A catalogue of semantic traps that each cost weeks, dominated by one
     class: **silent or uncatchable error paths**. kg has live instances
     (Phase 13).

Where a phase below cites "nelisp", the lesson's source doc lives under
`/opt/nelisp/docs/design/` and the citation is recorded in the phase so a
future reader can re-derive the rationale.

## Ground rules (all phases)

These restate standing project discipline; a phase agent reads this list
as binding.

- **fe-first pin discipline.** A change to fe lands as a commit in
  `fe/` (branch `more-elisp`) with fe's own suite green
  (`make -C fe check complexity-check pmccabe-check format-check`,
  `make -C fe compat`), then the kg-side commit moves the pin and adapts.
  The currently-uncommitted `.gitmodules` branch rename
  (`analyzers-etc` → `more-elisp`) rides with the first pin-moving kg
  commit of Phase 13.
- **Version macros.** A language-behaviour change bumps
  `FE_LANGUAGE_VERSION`; a C-contract change bumps `FE_API_VERSION`;
  the decision and its rationale are recorded in `doc/fe-upstream.md`'s
  running table, and `src/lisp_core.c`'s `static_assert`s move with the
  pin. Phase 10's precedent applies: even an addition-only language
  change bumps the language macro, because kg's compile-time tripwire is
  the point.
- **Manifests are exhaustive.** Every new fe primitive gets a
  `fe/compat/features.json` row; every new kg native or prelude
  definition gets a `test/lisp-compat/features.json` row. `make check`
  fails otherwise (`check_compat_manifest.py` / `check_lisp_compat.py`);
  do not "temporarily" silence that gate. A `planned` row with an oracle
  snapshot is a phase contract: freeze target semantics before
  implementing. A `divergent` row that starts agreeing is an XPASS
  failure — clean the row up, never ignore it.
- **Oracle snapshots** are produced by the runners
  (`make -C fe compat-oracle`, `make lisp-compat-oracle`), never written
  by hand, and only for fresh case names.
- **Ratchets.** scc/pmccabe/coverage/gateway ceilings are re-set at
  measured actuals with rationale + before/after proof in the commit
  message, never in a comment beside the knob.
- **Docs move with behaviour**: `README.md`, `doc/kg.1`, `src/help.c` +
  `make docs-check` for anything user-visible; `doc/lisp-api.md` for the
  Lisp surface; `doc/TODO.md` rows retired or updated when a phase
  lands what they record.
- **Green light** = `.ci/run-ci-steps.sh --parallel` all-PASS (the
  12-step run; ci-15-valgrind may stay SKIP locally). `make check` alone
  is an iteration signal, not a completion signal.
- **Never push.** Commits end with
  `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- **Untouchable**: the user's stashes, `/work/launch.sh`, and
  `doc/plans/2026-08-06_complexity-reduction-potential.md`.

## Phase 13 — Trustworthy errors

**Goal.** The condition system fe/kg already has must be trustworthy in
exactly the code an init file writes: nothing raisable escapes a
`condition-case`, nothing callable is misclassified, and kg natives
raise conditions a handler can actually name.

**Why first.** nelisp's costliest bug class — misdiagnosed for weeks,
twice — was silent/uncatchable error paths (an unbound variable silently
abandoning the rest of a top-level form, `/opt/nelisp` FINDINGS; a void
predicate aborting uncatchably, design doc 158). kg has two live
instances, found by the measured gap pass:

### 13.1 fe: `primitive_is_function[]` misclassifies `signal`, `error`, `keywordp`

Measured in both `fe/fe` and `test/kgbatch`:

```
(funcall 'signal 'error (list "x"))   => (invalid-function signal)
(apply 'error (list "boom"))          => (invalid-function error)
(mapcar 'keywordp (list :a 1))        => (invalid-function keywordp)
```

All three *do* evaluate their operands (they are functions in Emacs),
but lack rows in `primitive_is_function[]` (`fe/fe_eval.c:3245`), so
`IsRawFormCallable()` (`fe_eval.c:3322`) treats them as special forms.
This bug is recorded nowhere — no TODO, no manifest row. Work:

- fe: add the three rows; extend `test_api.c` with funcall/apply
  coverage for each; add compat cases (fe side) with oracle snapshots.
- Decide the `FE_LANGUAGE_VERSION` question in the fe commit (programs
  that raised now answer — by Phase 10's precedent that is a bump,
  10 → 11) and record it in `doc/fe-upstream.md` on the kg side.
- kg: pin move; `test/lisp-compat` cases exercising the same three
  through `kgbatch` (e.g. `mapcar 'keywordp` — the prelude `mapcar`
  funcalls).

### 13.2 kg: `lisp_raise_wrong_type()` escapes `condition-case`

Pre-existing, recorded in `doc/TODO.md`. `lisp_raise_wrong_type()`
(`src/lisp_core.c:713`) raises via a nested evaluation, so the
completion transfers past every lexically enclosing handler. The fix
shape is already implemented and documented *in the same file*:
`lisp_raise_file_condition()` (`src/lisp_core.c:786`) uses the
protected-call + `FeResignal()` route and its comment block explains why
the older shape is wrong. Work: convert `lisp_raise_wrong_type()` to
that shape; add a `kgbatch` unit + compat case proving
`(condition-case e (prefix-numeric-value "x") (wrong-type-argument 'caught))`
is caught (`src/lisp_cmd.c:272` is a caller to exercise).

### 13.3 kg: classify the native error surface

Today all ~87 kg natives raise a plain `error`, so
`(condition-case e (goto-char "x") (wrong-type-argument ...))` never
matches — manifest row `condition-case-native-errors`, `divergent`,
recorded as 06A Decision 2's deferred follow-up. nelisp's census of its
own evaluator found `wrong-type-argument` alone is **40% of all signal
sites** (design doc 88) — this one condition carries most of the value.
Work:

- Sweep `src/lisp_*.c` natives: type-check failures raise
  `wrong-type-argument` with Emacs' data shape (the predicate/expected
  symbol first, the offending value second); argument-range failures
  raise `args-out-of-range`; keep plain `error` only where Emacs itself
  is unstructured. Route everything through the (now fixed) raise
  helpers — no new raw raise sites.
- Flip `condition-case-native-errors` and per-native manifest rows from
  `divergent` to `supported` **only** where a fresh oracle snapshot
  agrees; the XPASS rule will police the rest.
- The `error-message` property ("Wrong type argument: listp, 6"
  rendering) is **not** this phase — it needs `get`/`put` (Phase 14) and
  lands in Phase 19.

### 13.4 The nelisp trap battery (pin, and fix only if red)

Each trap below became a multi-week hunt in nelisp. Land each as a
compat case with an oracle snapshot — *as tests, not prose* (nelisp's
own richest conformance batteries were never checked in as runnable
tests, a recorded anti-lesson from its design docs 159/160). Expected
outcome is mostly green (pinning), with any red case fixed in this
phase:

| Trap | Case | nelisp source |
|---|---|---|
| Chained variadic comparison | `(< 1 5 3)` → nil; `(<= 1 1 2)` → t; also `>`, `>=`, `=`, `/=` pairwise-all rule | doc 158: only args 0–1 compared; `rx` emitted garbled negated char classes |
| `catch`/`throw` with `t`/`nil` tags | `(catch t (throw t 1))` → 1, same for nil, nested mismatched tags | Makefile smoke: tag compare type-checked both operands as symbols; llama.el idiom |
| `declare` stripping | `(defun f (x) (declare (side-effect-free t)) x)` callable; docstring+declare+interactive positional cross-product | FINDINGS: live `(declare (debug ...))` walked as code |
| `format` argument consumption | already-strict in kg (`phase8-format-strictness` raises on unknown directives — raising cannot desync the argument cursor); pin that the *known* directives never desync | Makefile smoke: fallthrough arm emitted `%X` literally and did not consume |
| `setting-constant` for keywords/t/nil | pin existing behaviour | doc 88 census |

### 13.5 GC stress knob

nelisp shipped a GC that was never invoked (COLL=0 across a 2.4 GB run,
design doc 152), and separately had a use-after-free *masked* by
unrelated churn-reduction speed work (doc 155). Defence: a fe build/env
knob (e.g. `FE_GC_STRESS`, following the `KG_FUZZ`/`KG_PERF_COUNTERS`
compile-to-nothing pattern) that collects on every allocation, wired
into at least one fe test lane and one `kgbatch`-driven kg case. Also
assert somewhere cheap that a heavy-allocation script reports a nonzero
collection count via the existing arena-stats surface.

**Definition of done (13).** All 13.1–13.5 landed; fe suite + compat
green at the new pin; kg 12-step parallel CI green;
`doc/fe-upstream.md` updated; `doc/TODO.md` rows for 13.2/13.3 retired;
report includes the measured before/after for every flipped manifest row.

## Phase 14 — Symbols and reader escapes

**Goal.** First-class symbol operations: `intern`, `intern-soft`,
`symbol-name`, `make-symbol`, `gensym`, `put`, `get` — plus reader
symbol escapes. This is the phase `doc/TODO.md` already names as the
prerequisite that three blocked items collapse onto: backquote
*spelling* in the printer/prelude (reader escapes first, spelling
second, per the TODO's own two-phase note), the ~54 dynamically
capturable `internal--let` prelude temporaries (gensym is the fix), and
the `error-message` property (needs `get`; consumed by Phase 19).

**Work items.**

- fe: `intern`, `intern-soft`, `symbol-name`, `make-symbol` (uninterned
  — decide and record how uninterned symbols print and compare),
  `gensym`, `put`/`get` (symbol plists). Reader: backslash escapes in
  symbol names, superseding the current named
  `reader-hash-syntax-unsupported`-style rejection for `\` — keep the
  strict-reader policy for everything not deliberately opened.
- **The intern-soft contract is the trap** (nelisp doc 163): it must
  return nil on a miss and must NOT intern as a side effect — Gnus'
  `message.el` runs `(while (setq x (intern-soft (format ...))) ...)`
  and an insert-on-miss implementation allocates until OOM. Pin with
  the double-probe test: two consecutive `intern-soft` calls on a fresh
  name both nil; after `intern`, non-nil.
- fe printer: symbols whose names need escapes print re-readably.
- kg: pin move, manifest rows, oracle snapshots. Language version bumps
  (new names + reader acceptance change).
- Follow-up made possible but NOT in-phase: converting prelude
  temporaries to gensym (do it only if small; otherwise record as its
  own TODO row now unblocked).

**Definition of done (14).** Names above measured against oracle;
`(gensym)`-based hygiene demonstrated in at least one prelude macro;
double-probe intern-soft case green; CI green; `doc/fe-upstream.md` +
TODO updated (blocked-on-intern rows re-pointed).

## Phase 15 — The package-writer's string/list library

**Goal.** Close the single largest measured blocker for writing any
real package: strings, list utilities, and the regex-from-Lisp seam.

**Method first: the forecast audit.** Before implementing, build the
tool (nelisp's best process artifact, design docs 11/13):

- `utils/forecast_audit.py` (or `.el` driven by the pinned oracle
  Emacs): scan a corpus of *target* Lisp files for symbols in function
  position plus `#'sym` / `'sym` arguments to `funcall`/`apply`/`mapcar`
  etc.; parse fe's + kg's implemented-name set out of the sources /
  manifests (so it cannot drift); emit a checked-in
  `MISSING`/`COVERED` partition sorted by reference count, and gate it
  in CI with a regenerate-and-diff step (nelisp stopped one step short
  of gating; we don't).
- Corpus (checked in under `utils/forecast/`): kg's shipped
  `lisp/*.el`; a hand-written realistic `target-init.el` (keybindings,
  a hook, a small command, a mode tweak); 2–3 forecast sketches in
  nelisp's style for packages we *want* (e.g. a grep/occur helper, a
  simple templating/snippet package). Hand-written sketches avoid
  vendoring/licensing questions and state intent.

The audit's ranked MISSING list is the implementation order; the list
below is the expected shape, to be corrected by measurement:

- **Natives (kg or fe as appropriate):** `string-match`, `match-string`,
  `replace-regexp-in-string`, `regexp-quote` (the regex engine exists —
  `src/regex.h` — this is a seam, not an engine); `string-to-number`;
  `upcase`/`downcase`/`capitalize` (string forms); generalize `length`
  over strings (today prelude `length` is list-only and `string-length`
  is a kg-only name — reconcile, keep char-indexing: kg natives are
  already codepoint-indexed, which nelisp's doc 161 identifies as the
  keystone property; byte access, if ever needed, gets a separate name).
- **Prelude Lisp (zero C):** `split-string`, `string-join`,
  `string-trim`/`-left`/`-right`, `string-prefix-p`/`string-suffix-p`,
  `string<`, `string-empty-p` exists; `alist-get`, `plist-get`/
  `plist-put` (list form; symbol `put`/`get` landed in 14), `sort`
  (list merge sort), `elt` (list+string), `caddr`/`cdar`/… family,
  `butlast`, `copy-sequence` (lists), `number-sequence`, small `seq-`
  shim (`seq-filter`/`seq-map`/`seq-find`/`seq-some`), `mapcan`,
  `abs`, `mod`, `%`, `logand`/`logior`/`logxor`/`ash`
  (fe natives if cheap, prelude otherwise).
- **Explicitly not here:** hash tables, vectors, records (see Declined
  below — the forecast audit is also this decision's re-answering
  instrument: report their demand counts).

**Definition of done (15).** Forecast tool + corpus + CI gate landed;
every implemented name has a manifest row and oracle snapshot; the
`target-init.el` loads clean under `kgbatch`; the audit report shows
the residual MISSING tail with counts (so Phase 17's package milestone
can be scoped honestly); CI green.

## Phase 16 — Prompting (minibuffer reads)

**Goal.** A Lisp command can ask the user something mid-body, not only
via `interactive` codes. This is `doc/TODO.md`'s "Phase 8 read
functions" item: the pickers exist in C since 07E — this phase is
exposure, not construction.

**Work items.** Public `read-string`, `read-number`, `read-file-name`,
`read-buffer` with Emacs' optional arguments where kg has substance
(PROMPT, DEFAULT; history only if the minibuffer already keeps one —
otherwise accept-and-ignore is a recorded divergence, not a stub error);
`y-or-n-p`, `yes-or-no-p`; `completing-read` over a list-of-strings
COLLECTION (predicate/complex tables are recorded divergence).

the 07E non-command re-entry note applies; C-g must land as `quit`
catchable by `condition-case` and must not wedge the editor. Each gets
PTY cases (these cannot be oracle-compared for values — `kg-policy`
comparison, pinned by named kg tests, per the existing convention), plus
`kgbatch` cases for the argument-validation/`quit` paths.

**Definition of done (16).** All six callable from a user command in a
PTY case; C-g path pinned; manifest rows (`kg-policy`) + docs
(`doc/lisp-api.md`, README example) landed; CI green.

**Work items.**

## Phase 18 — Buffer-local variables and hook coverage

**Goal.** The single largest editor-model gap, and the only L-sized
design in the wave. Today `setq-local` and `setq-default` are aliases
of `setq` — manifest rows say `divergent`, i.e. they *lie* rather than
err.

**Design constraints (to be turned into a short design section in the
implementing commit, not a separate doc):**

- Per-buffer binding table; lookup order: buffer-local binding, else
  global/special binding. `make-local-variable` semantics on
  `setq-local`. Lifetime: killed with the buffer; switching buffers
  switches visibility. Interaction with `defvar` specials and `let`
  shallow binding must be specified *first* (what does `let` over a
  name that is buffer-local in the current buffer bind?) — write the
  contract as `planned` manifest rows with oracle snapshots before
  implementing (the phase-contract pattern).
- Storage lives on the kg side (buffers are kg's), reaching fe through
  the existing value-cell seam; fe grows at most a hook, not a buffer
  concept. If a fe-side mechanism is unavoidable, it must be justified
  against the nelisp layer-boundary lesson (design doc 141: the
  language runtime owns no editor objects).
- `fill-column` in `auto-fill.el` becomes the first real consumer
  (today it is global — measured).
- **Hooks:** `kill-buffer-hook`, and `post-command-hook` *only with the
  measurement the TODO demands* — per-keystroke cost with `test_perf`
  counters (the perf harness exists precisely for this), with the
  result recorded in the commit whether it lands or stays declined.
  Hook-error containment policy stays kg's (`hook-error-does-not-disarm`
  is a recorded divergence, not a bug).

**Definition of done (18).** Contract rows frozen before code;
`setq-local`/`setq-default` rows flip from `divergent` to `supported`
(or to a *narrower, honest* divergence with the surviving delta named);
`auto-fill.el` uses a buffer-local `fill-column` with a two-buffer PTY
case proving isolation; hook additions measured; CI green.

## Phase 19 — Discoverability

**Goal.** Make the Lisp surface self-describing from inside kg.

**Work items.**

- Docstrings for prelude definitions (today `(documentation 'mapcar)`
  → nil, measured); keep the single name-keyed alist mechanism unless
  it measures as a startup cost (then reconsider — nelisp's baked-image
  lesson: definitions persist, side effects don't; kg's generated-inc
  prelude embedding has the same shape).
- `describe-function`, `describe-variable`, `apropos` — kg-policy
  surface (rendering into a buffer), PTY-tested.
- **The `interactive-form` metadata decision** (TODO item: 07D stores
  the spec *thunk*, not the raw form). Decide: store the raw spec
  alongside the thunk; expose `interactive-form`; make `commandp`
  answer from it. This is deliberately last-ish: Phases 16–17 add the
  commands that make the reflection worth having.
- `error-message-string` + per-symbol `error-message` property (unblocked
  by Phase 14's `put`/`get`), fixing the measured gap that
  `(signal 'wrong-type-argument '(listp 6))` reports a bare symbol.
- `defvaralias` if trivially reachable (measured absence is why
  `inhibit-startup-screen`/`-message` are two variables today);
  otherwise record.

**Definition of done (19).** `C-h`-style discovery of a user-defined
command works in a PTY case; `error-message-string` output matches the
oracle for the standard hierarchy; manifests/docs updated; CI green.

## Declined and watch items (unchanged by this plan)

- **Bytecode**: declined 2026-08-07 with counters; the five triggers
  and the "fund instrumentation first" rule stand.
- **Hash tables / vectors / records**: off-roadmap per
  `fe/compat/features.json`. *Watch item*: nelisp's measured demand put
  `aref` at #15 and `puthash` at #22 — but that corpus was a
  self-hosting compiler. Phase 15's forecast audit re-answers this with
  kg-relevant data; a nonzero verdict is recorded in the audit output
  either way, and reopening requires its own phase with that evidence.
- **`eval`'s LEXICAL argument, macro environments**: need first-class
  lexical environments; recorded, not planned.
- **Frame-limit raising, GC back-pressure**: measured useless; stands.
- **`unwind-protect` cleanup-delivery residuals**: "a different unwind
  model, not a bug fix"; stands.

## Sequencing rationale (one paragraph, for the record)

Trust before surface: Phase 13 makes error behaviour testable against
the oracle, which every later phase's cases lean on. Symbols (14) are
the named prerequisite of three blocked TODO rows and of Phase 19's
error rendering. Strings (15) are the measured top blocker for any
package and produce, via the forecast audit, the evidence that scopes
17's package milestone and re-answers the vectors/hash question.
Prompting (16) and editor reach (17) are independent of each other but
both feed the package milestone. Buffer-locals (18) are the hardest
design and deliberately come after the audit has shown which packages
actually demand them. Discoverability (19) is polish that pays off only
once there is a surface worth describing.
