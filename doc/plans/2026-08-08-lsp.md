# LSP support: optional clangd/ty client with xref commands

Goal: optional LSP support, first servers clangd (C/C++) and ty (Python).
Must-haves: goto definition and find references, surfaced as the Emacs
commands `xref-find-definitions` (M-.) and `xref-find-references` (M-?).

Scope discipline: LSP as an asynchronous xref backend, nothing more.
Diagnostics, completion, hover, rename, semantic tokens, code actions and
formatting are explicitly out of scope until the xref foundation has
proven itself. LSP is independent of both Lisp and tree-sitter: it must
work in a `WITH_LISP=0` build and carries no `KG_USE_LISP` or
`KG_USE_TREE_SITTER` conditionals.

## Verified repo facts this plan builds on

These were checked against the tree on 2026-08-08; stage instructions
below assume them.

- **Build axis.** Optional features are source-list axes, not #ifdef
  forests: `LISP_SRCS`/`SYNTAX_BACKEND_SRCS` in the Makefile, one shared
  feature stamp `FEATURE_CONFIG = $(OBJDIR)/.features-lisp-$(WITH_LISP)-ts-$(WITH_TREE_SITTER)`
  (Makefile ~161) whose *name* must gain `-lsp-$(WITH_LSP)` — a second
  stamp file would break cross-axis rebuilds. `kg -V` prints one
  `+word`/`-word` per feature (src/main.c:169); every `+word` is
  automatically a PTY `requires_feature:` name (utils/pty_accept.py:830
  builds the feature set from `-V` output), so `requires_feature: lsp`
  costs nothing once `-V` says `+lsp`.
- **Default on.** Unlike tree-sitter, LSP has no build-time dependency —
  servers are found at runtime. So `WITH_LSP ?= 1`, with a
  `.ci/ci-14-with-lsp-0.sh` proving the disabled build (mirror of
  ci-08-with-lisp-0.sh). Defaulting to 0 would mean the main CI lanes
  never compile or test the client.
- **Process layer.** `kg_process_spawn()` (src/process.c) already takes a
  caller-provided `stdin_fd` and owns fork/exec/process-group/CLOEXEC
  machinery, but returns only the child's stdout read fd. Nothing today
  writes to a child's stdin incrementally (shell.c's `pump_io()` is a
  synchronous one-shot). The process table is the wrong home: it has no
  stdin path and delivers output as buffer text at event-drain safe
  points. LSP gets its own transport on a new `kg_process_spawn_bidi()`.
- **No SIGCHLD handler exists, by design.** Reaping is poll-driven
  `waitpid(WNOHANG)` from each subsystem's poll (`kg_process_reap()`).
  The LSP client reaps its own children the same way; a SIGCHLD handler
  would race the existing reapers and steal their statuses.
- **Poll sites are two, not one.** The main loop (src/main.c:201-237)
  polls compilation/autorevert/process-table then drains events — but the
  loop actually *blocks* in `read_key_byte()` (src/tty.c:580-620) under
  `VMIN=0, VTIME=1`, whose 100 ms idle timeouts re-run the polls.
  `lsp_poll()` must be added at **both** sites (main.c beside
  `kg_process_table_poll()`, tty.c idle path) or responses stall while
  the editor waits for a key. Precedent says poll-time work may touch
  special buffers and the echo area (compile.c does) and even replace
  buffer contents (autorevert), so xref responses may navigate directly
  from the poll.
- **Events carry no text.** `KG_EVENT_BUFFER_CHANGED` gives byte ranges
  and generations only, and coalesces to broad-change summaries under
  pressure (src/event.h contract). Document sync therefore cannot replay
  edits from events; it compares `content_generation` (bumped once per
  content change, never reset — the vgeom.c cache-key pattern) against a
  shadow snapshot, lazily, before each request.
- **Positions.** Buffer columns are UTF-8 byte offsets into `row->chars`
  (doc/coordinates.md); `editor_rows_to_string()` joins rows with `\n`
  and no trailing newline — that string is what shadows store and what
  offsets index. LSP wants (line, character) with a negotiated encoding:
  UTF-8 preferred (free for kg), UTF-16 implemented correctly as the
  mandatory fallback.
- **Keymaps are full and the predicates leak.** `keymap_max_maps` is 8;
  seven built-ins plus the lazily created user map consume all of them,
  and Lisp `(define-key ...)` can create more on demand. Worse,
  `key_update_mode_maps()` (src/kbd.c:606-623) activates
  `MODE_MAP_BUFFER_LIST` for *any* read-only non-dired buffer — a
  read-only `*xref*` buffer would inherit `RET → ibuffer-visit-buffer`
  and the wrong `q`. The xref stage must raise the bound *and* tighten
  the predicates, with regression tests for both.
- **M-. and M-? are free.** Keys are `struct key_event { base, mods }`;
  `M-.` is `{'.', KEY_MOD_META}` and dispatch falls through to
  self-insert (which drops Meta non-printables) today. A keymap row
  `{ "M-.", "xref-find-definitions" }` just works.
- **Command table constraints** (test/test_cmd.c): sorted unique names,
  handler non-NULL, summary ≤60 columns with no trailing period, and the
  `CMD_LISP_CALLABLE` set is locked to an explicit list — new xref
  commands stay non-Lisp-callable for now to avoid growing that set.
- **Navigation exists but is compilation-private.** compile_nav.c's
  `nav_pick_window()`/`nav_open_source()`/`editor_goto_line_direct()`
  are exactly what xref needs, but static, and `nav_pick_window()`
  closes over the compilation buffer. Extract a shared
  `editor_visit_file_position(path, line, col, from_buffer)` used by
  both.
- **No JSON anywhere** in src/ or vendored code. `lsp_json.c` is new,
  dependency-free, and small (tokenizer + serializer sufficient for
  JSON-RPC — no need for a general DOM beyond what requests/responses
  use).
- **Ratchets a new module must respect**: scc total cap
  (`SCC_COMPLEXITY_MAX`, Makefile ~1056) must be raised with a dated
  ledger entry in the comment block above it, in the established
  bisect-proof style; per-file scc cap is 520, so keep files under it;
  every new function must measure ≤15 in pmccabe (no baseline entry
  needed if so); the mutation gateway and coverage baselines need no
  up-front entries (a file with no row-primitive hits never appears in
  the gateway; new files are coverage notes, not failures — but the
  TOTAL function-rate floor has zero slack, so land tests with the code
  and re-bank `make coverage-baseline` once the feature is in, with the
  reason in the commit). `make header-check` picks up new src/*.h
  automatically — each must compile standalone. `make lisp-include-check`
  forbids `fe.h`/`lisp_internal.h` outside the Lisp adapters.

## Architecture

```
xref.c            commands, *xref* buffer, go-back stack, navigation
   │   knows nothing about clangd/ty or JSON
lsp.h             the one editor-facing facade (+ WITH_LSP=0 inline stubs)
lsp_client.c      JSON-RPC lifecycle: ids, callbacks, capabilities,
                  initialize/shutdown, crash detection
lsp_server.c      server specs (mode → argv), instances keyed by
                  (server kind, workspace root), root detection, lazy start
lsp_sync.c        didOpen/didChange/didClose, shadow snapshots,
                  position encoding (utf-8/utf-16), file URIs
lsp_transport.c   kg_process_spawn_bidi() consumer: Content-Length
                  framing, bounded in/out buffers, nonblocking writes
lsp_json.c        dependency-free JSON tokenizer/serializer
```

Dependency direction is strictly downward; lsp_sync knows nothing about
xref, and only lsp_server.c knows server names. Under `WITH_LSP=0` none
of `lsp_*.c`/`xref.c` compile; `lsp.h` provides static-inline no-op
stubs (the `syntax` backend split is the model) so callers stay
conditional-free.

Server policy: instances keyed by (kind, workspace root), started
lazily by the first xref command — opening a .c file spawns nothing.
Built-in specs: `clangd` for `KG_MODE_C`, `ty server` for
`KG_MODE_PYTHON` (the syntax registry's `enum kg_mode_id` is dense, so
the spec table is a flat array). An environment override
`KG_LSP_SERVER_<MODE>` (e.g. `KG_LSP_SERVER_C="python3 fake.py"`) exists
from day one — it is how every deterministic test injects the fake
server, and how users point at a differently named binary.

Workspace root: nearest ancestor with (C) `.clangd`,
`compile_commands.json`, `compile_flags.txt`, `build/compile_commands.json`;
(Python) `ty.toml`, `pyproject.toml` containing `[tool.ty`; then `.git`;
then the file's directory.

Testing strategy: a deterministic Python fake LSP server
(`test/fake_lsp_server.py`) speaks just enough protocol —
initialize/initialized, definition, references, shutdown/exit, plus
scripted misbehaviors (garbage bytes, oversized Content-Length, split
and batched frames, exit mid-request) selected by argv. Native tests
(`test/test_lsp_*.c`) cover framing, JSON, sync and positions; PTY
cases with `requires_feature: lsp` cover M-./M-? end-to-end against the
fake server; real clangd/ty cases SKIP when the binary is absent, in
the suite's established skip-with-reason style.

## Stages

Each stage is one reviewable, committable slice ending with
`make check` green (plus `make complexity-check`); user-visible changes
carry their README/kg.1/help.c updates in the same slice.

### Stage 0 — feature axis and facade
`WITH_LSP ?= 1` with 0/1 validation; `LSP_SRCS` interpolated into
`SRCS`; extend the `FEATURE_CONFIG` stamp name; `-DKG_USE_LSP=1` in
CFLAGS (and FUZZ_CFLAGS, which is a complete flag set, not an
increment); `kg -V` gains `+lsp`/`-lsp` via a `KG_FEATURE_LSP` macro in
main.c. `src/lsp.h` with the full public surface as stubs:
init/shutdown, `lsp_poll()`, attach/sync notions, request entry points —
compiled but inert. `.ci/ci-14-with-lsp-0.sh` proves `WITH_LSP=0` (and
one orthogonality run `WITH_LISP=0 WITH_LSP=1`). scc ledger entry for
the raise. Deliverable: all feature combinations build and pass
`make check`.

### Stage 1 — bidirectional transport
`kg_process_spawn_bidi()` in process.c: same spawn machinery, returns
child pid, nonblocking parent read fd *and* nonblocking write fd;
child's stderr to /dev/null for now (an `*lsp-log*` buffer is a later
nicety). `lsp_transport.c`: Content-Length framing with headers split
across reads, multiple messages per read, bounded inbound buffer
(oversized message ⇒ transport error, not OOM), bounded outbound queue
with nonblocking writes and EPIPE/EAGAIN handling (SIGPIPE must not
kill the editor — write with MSG_NOSIGNAL semantics via ignored SIGPIPE
as shell.c does, but non-blocking). `test/fake_lsp_server.py` (echo +
scripted-frames modes) and `test/test_lsp_transport.c` driving a real
child process. No protocol knowledge yet.

### Stage 2 — JSON layer
`lsp_json.c`: event/tree parser sufficient for JSON-RPC (objects,
arrays, strings with escapes incl. \uXXXX and surrogate pairs, numbers,
bools, null; UTF-8 output), a small writer, and typed getters
(`lsp_json_obj_get`, string/int extraction). Depth- and size-bounded.
`test/test_lsp_json.c` including malformed-input cases. Pure logic, no
editor linkage.

### Stage 3 — JSON-RPC client and server registry
`lsp_client.c`: request-id allocation, bounded pending-request table
with callbacks, `initialize` → `initialized` handshake, capability
capture (position encoding, sync kind), graceful `shutdown` → `exit`
with bounded wait then SIGTERM/SIGKILL (reuse
`kg_process_table`-style terminate semantics), `WNOHANG` reaping and
crash detection ("server dead; restarts lazily on next command"),
unknown notifications ignored, unknown server *requests* answered with
JSON-RPC MethodNotFound rather than left hanging. `lsp_server.c`: spec
table, env override, instance registry keyed by (kind, root), root
detection per the policy above. `lsp_poll()` wired at both poll sites.
Tests against the fake server: handshake, request/response matching,
server crash mid-request, shutdown.

### Stage 4 — document sync and positions
`lsp_sync.c`: per-document shadow (last-sent text + generation +
version counter). Before each request: dead buffer handle ⇒ didClose;
new buffer ⇒ didOpen (full text); changed generation ⇒ didChange —
longest common prefix/suffix against the shadow yields one contiguous
replacement for incremental-sync servers, whole text for full-sync
servers; then the shadow is replaced. Position helpers: (row, byte col)
⇄ LSP (line, character) for utf-8 and utf-16 (utf-16 conversion walks
`row->chars` counting code units), plus file-URI encode/decode
(percent-encoding, `file://` only — reject anything else). Native tests
with multibyte fixtures on both encodings; sync tests via fake server
asserting exact didChange payloads.

### Stage 5 — M-. xref-find-definitions
Extract `editor_visit_file_position()` from compile_nav.c (parameterize
the "results buffer to escape from"); compile_nav keeps its
marker-based revisit logic on top. `xref.c`: `xref-find-definitions`
command — sync dirty docs, send `textDocument/definition`, echo
"Finding definition..."; async handler accepts Location | Location[] |
LocationLink[]; zero ⇒ "No definition found", one ⇒ visit, many ⇒ the
*xref* buffer (delivered in Stage 6; until then, visit the first and
say "N candidates"). Push the departure point onto a new global go-back
stack (buffer handle + marker, compile_nav_extra pattern) even though
M-, itself lands in Stage 7. Global map rows for `M-.`; cmdtable rows;
README/kg.1/help.c updates; PTY case: fake server, C file, M-. lands
point at the right spot; second case for "no definition".

### Stage 6 — M-? and the *xref* buffer
Read-only `*xref*` buffer via `buf_prepare_special_text()`:
`path:line:col: preview` lines, bounded (cap entries, visible
truncation marker — the describe.c bounded-page pattern). Raise
`keymap_max_maps` (8 → at least 10) with a regression test that the
user C-c map still works with an xref map installed; add
`MODE_MAP_XREF` (`RET` visit, `n`/`p` move, `q` quit) and tighten
`key_update_mode_maps()` predicates so *xref* doesn't also match the
buffer-list map. `xref-find-references` always lists, even for one
result. Multi-result M-. now lists too. Docs + PTY cases (references
across two files via fake server; RET visits; q closes).

### Stage 7 — lifecycle hardening and M-,
Buffer kill ⇒ didClose (subscribe to `KG_EVENT_BUFFER_KILLED`; the
event-subscriber budget is 16 with 2 used); editor exit ⇒ graceful
shutdown of all instances (bufmgr.c `editor_cleanup()` beside
`kg_process_table_shutdown()`); responses arriving for dead buffers
dropped via generation-checked handles. `xref-go-back` on `M-,`
popping the Stage-5 stack. Fake-server misbehavior tests: garbage
bytes, oversized frame, split/batched frames, exit mid-request, reply
after buffer killed. Docs.

### Stage 8 — real servers and polish
Optional real-server tests, skipping with a printed reason when the
binary is missing: clangd against a two-file fixture with
`compile_commands.json` (definition and references across translation
units); ty against a small package with `pyproject.toml` +
`[tool.ty]` and a cross-module import. Workspace-root unit tests.
UTF-16 default-encoding path exercised against clangd (it negotiates
utf-8; force the fallback in a unit test if clangd won't). Final docs
sweep: README "LSP (optional)" section modeled on the tree-sitter one,
kg.1 `.Sh LSP`, doc/TODO.md follow-ups (diagnostics, hover, rename,
*lsp-log* buffer, fuzz target for the frame parser, gopls/rust-analyzer
specs) — written down, not implemented. Re-bank `make
coverage-baseline` with the feature landed.

## Out of scope (recorded, deliberate)
Diagnostics, completion, hover, rename, formatting, semantic tokens,
code actions, workspace/didChangeWatchedFiles, multiple roots per
server instance, `*lsp-log*`, fuzz harness for framing (follow-up),
Lisp bindings for xref (follow-up once the command set stabilizes).
