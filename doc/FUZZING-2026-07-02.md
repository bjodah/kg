# Fuzzing Campaign 2026-07-02

## Scope

Ran the keypress libFuzzer target with 24 fork workers:

```sh
./test/fuzz_keypress -max_total_time=900 -fork=24 \
  -artifact_prefix=test/fuzz-artifacts/<run>/ test/fuzz-corpus/keypress
```

The campaign did not complete one uninterrupted 15 minute clean run.  Each
long run stopped early on a crash candidate, and the time was spent triaging
and fixing the low-hanging, reproducible findings.

## Fixed Findings

- `editor_del_forward_char()` read past EOL when rectangle mark mode left the
  cursor in virtual space.  Confirmed with PTY regression
  `test/pty/28-rect-virtual-forward-delete.yaml`.
- `editor_kill_line()` joined the next line from rectangle virtual space.
  Covered by `test/pty/29-rect-virtual-kill-line.yaml`.
- `editor_move_cursor(ARROW_LEFT)` could make `cy` negative when moving left at
  BOL from the top row of a scrolled viewport.  Covered by
  `test/pty/30-left-scroll-bol-previous-line.yaml`.
- `editor_reflow_paragraph()` deleted whitespace-only paragraphs, leaving later
  sentence movement with stale row state.  Covered by
  `test/pty/31-reflow-space-only-sentence-backward.yaml`.
- `editor_undo()` trusted stale split/join columns and could write past a
  shortened row.  Covered by `test_split_line_short_row` in
  `test/test_undo.c`.
- `editor_join_line()` read a stale row when the cursor row was outside the
  current buffer after row-replacing edits.

All crash artifacts collected during this session replay clean after the fixes.

## Follow-up Campaign

Ran additional keypress libFuzzer attempts with the same 24-worker command:

```sh
./test/fuzz_keypress -max_total_time=900 -fork=24 \
  -artifact_prefix=test/fuzz-artifacts/2026-07-02-codex-900s-<n>/ \
  test/fuzz-corpus/keypress
```

The follow-up campaign also did not reach one uninterrupted clean 900 second
run.  Each long attempt stopped on an actionable artifact, and the session was
spent replaying, reducing where practical, and fixing the low-hanging crashes.

Additional fixed findings:

- The fuzzer leaked static keyboard macro recorder state between inputs, which
  produced a non-standalone `editor_move_cursor(ARROW_LEFT)` artifact.  Added a
  fuzzer reset hook for macro state so future crash files are self-contained.
- Generated fuzz corpora/artifacts were not ignored even though they are
  generated analysis output.  Added ignore rules for `test/fuzz-corpus/` and
  `test/fuzz-artifacts/`.
- `editor_kill_word_backward()` could corrupt a row when `C-x C-x` moved point
  to a stale mark past EOL and `M-Backspace` killed from that virtual column.
  Confirmed with PTY regression
  `test/pty/32-forward-delete-after-mark-exchange.yaml`.
- `editor_move_cursor(ARROW_LEFT)` trusted stale cursor rows after row-deleting
  edits and read beyond the live row array.  Covered by
  `test_left_from_stale_row_clamps_to_eof` in `test/test_basic.c`.
- `editor_move_sentence_backward()` trusted stale cursor rows after a region
  kill deleted rows, and could read freed row storage.  Covered by
  `test_sentence_backward_clamps_stale_row` in `test/test_word.c`.
- `editor_move_word_backward()` trusted stale virtual columns and could read
  past short rows.  Covered by `test_word_backward_clamps_stale_column` in
  `test/test_word.c`.
- `editor_kill_word_forward()` now rejects stale columns past EOL and clamps
  negative columns before measuring the word kill range, matching the new
  backward word-kill guard.

All crash artifacts collected during the follow-up replay clean after the fixes.
