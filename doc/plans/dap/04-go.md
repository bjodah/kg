# DAP subplan 04 — Go via delve (measured)

Parent: `doc/plans/2026-08-11-dap.md`; prerequisites: subplans 00-02
(shares the announce-scanner work with 03-java; either adapter extension
can land first). Everything below was measured live on this box on
2026-08-11: dlv 1.27.1 (`/root/go/bin/dlv`, Go toolchain on PATH),
both `mode:"debug"` (delve builds) and `mode:"exec"` (prebuilt binary)
driven end-to-end with zero failures, plus a deliberate build-error run.

## Verdict

Feasible, and the cleanest adapter of the four measured: delve verifies
breakpoints synchronously, is the only one that populates
`allThreadsStopped` *and* `hitBreakpointIds`, emits `exited` +
`terminated`, and **correctly errors on a stale `variablesReference`**
(`stop_epoch` remains defense in depth here, required elsewhere).
Zero reverse requests. Round trips 0-3 ms — the fastest measured.

## Connection shape: spawn-then-scrape-port-then-connect

`dlv dap` is **TCP-only** — no stdio mode exists. kg spawns
`dlv dap --listen 127.0.0.1:0`, scrapes stdout, connects, no handshake:

```
DAP server listening at: 127.0.0.1:<port>\n     (stdout, once, LF only)
```

The transport owns more than stdio does — child pid/process group, the
child's stdout announce/log channel, its stderr log channel, and the
DAP socket — through an explicit state machine:

```
SPAWNING → WAIT_ANNOUNCE → CONNECTING → OPEN
                       any failure → CLOSING → DEAD
```

Before OPEN, stdout is scanned incrementally and still drained to a
bounded log destination; after OPEN it stays a log channel and never
becomes the frame stream. stderr is always drained. Child EOF before
the announce is a startup failure; stdout EOF after connect is not
socket EOF; child exit/reap at any point is a terminal adapter failure.
Every failure/cancel path closes socket and log fds, signals the owned
process group and reaps it. kg never globs or deletes `__debug_bin*` —
delve owns its build artifact's cleanup.

Measured constraints:

- **Startup to listening: 4-10 ms.**
- **Never pass `--log-dest`** in the built-in argv — it moves the
  announce off stdout and silently defeats the scraper (measured: first
  run timed out on exactly this). A custom adapter config can still do
  it to itself; the failure mode is the announce deadline, whose error
  message names the expected prefix and the command run — not a
  generic initialize timeout.
- **The announce prefix must include the host and the parse is
  strict**: `"DAP server listening at: 127.0.0.1:"`, then decimal
  digits only, range 1-65535, connecting **only to loopback** — with a
  bare `"...listening at: "` prefix a digits-scan reads `127` out of
  `127.0.0.1`, and more importantly a log line must never be able to
  redirect kg to an arbitrary host (a trusted host belongs in an
  explicit config field, not in announce text). Safe because kg
  chooses `--listen`.
- `--client-addr` (delve dials out to a listening client, `unix:`
  supported) exists — a possible future alternative to scraping;
  recorded, not planned.

This folds into the announce scanner built for nbcode (subplan 00-A /
03-java) with one flag: the scanner's three knobs are *prefix*,
*optional secret separator*, *what to write on connect*. delve =
(prefix, none, nothing); nbcode = (prefix, `" with hash "`, the hash);
jdtls = no scan (port via executeCommand → `attach_socket`). Measured
diff for all three parameterizations together: 117 lines on today's
`lsp_transport.{c,h}`.

## Measured choreography

Launch response arrives **after `initialized`, before
`configurationDone`** — same slot as nbcode (four adapters, three
distinct orderings; the accept-anytime invariant stands). Notables:

- `process` event (full body) arrives *before* `initialized`.
- Breakpoints verify **synchronously** in the `setBreakpoints`
  response, with ids and echoed source; clearing returns
  `"breakpoints": []`. No `breakpoint` events needed.
- `stopped` is the reference shape:
  `{reason:"breakpoint", threadId, allThreadsStopped:true,
  hitBreakpointIds:[1]}`; step stops say `reason:"step"`.
- `continued {threadId, allThreadsContinued:true}` arrives *before*
  the step response.
- Teardown: `exited{exitCode}` then `terminated{}`, then a **second**
  `terminated{}` after `disconnect` — duplicate `terminated` must be
  tolerated (the lattice already is idempotent) — then the process
  exits (ERR_EOF; reconnect to the port refuses).
- **Goroutines are threads**: names like
  `"* [Go 1] main.compute (Thread 109642)"`, `*` marking the current
  goroutine. Render as-is. One scope, `"Locals"`; runtime frames carry
  real source paths into `$GOROOT` (the non-navigable/user-frame
  preference from subplan 01 applies).
- `evaluate`: `hover`/`watch`/`repl` returned identical results
  (measured); `repl` context additionally accepts delve's own commands
  (`dlv config -list` worked) — a free richer `*dap-repl*` for Go.
- Latency: initialize 6-7 ms; `mode:"debug"` launch is dominated by the
  Go build (1.53 s cold, 0.32 s warm); `mode:"exec"` launch 0.245 s.

Capabilities (delta from the parent matrix): `restart` **true** (the
only adapter of the four with it at initialize), `terminate` absent —
`disconnect` is the only teardown verb; granularity + instruction
breakpoints + disassemble + read/write memory + data breakpoints all
true; `gotoTargets`/`stepInTargets`/`completions` absent.
`exceptionBreakpointFilters`: `unrecovered-panic` and
`runtime-fatal-throw`, **both default true** — honoring defaults gives
panic stops for free.

## Go-specific behaviors kg must handle

1. **Debuggee output arrives on delve's own stderr, not as `output`
   events** (measured; this is why dape's dlv config carries
   `command-insert-stderr`). The adapter-spec flag is named for what it
   does — `route_adapter_stderr_to_output` — because the same fd also
   carries delve's own diagnostics and kg cannot classify the mix. And
   the bytes must arrive as *bytes*: the transport's stderr channel is
   line-shaped with a 4096-byte chunk bound, so either the child/log
   layer grows a byte-drain callback (line scanning stays for the
   announce phase) or chunks are reconstructed with their original
   newline/tail state — never a newline invented per
   `next_stderr_line()` result, which would rewrite the debuggee's
   output at chunk boundaries. `output` events carry only delve's own
   chatter (`Building ...` on stdout-category, the help hint on
   console, build failures on stderr-category).
2. **Build failures (`mode:"debug"`)**: the launch response says only
   "Check the debug console for details"; the actual
   `./main.go:14:16: syntax error: ...` arrives *earlier* as
   `output{category:"stderr"}` events. kg buffers launch-phase output
   (bounded — 4 MiB + truncation notice, matching compilation policy;
   "buffer until we know" must not be unbounded) and on launch failure
   feeds it into compilation navigation. That is a **new seam, not a
   call**: nothing public turns arbitrary bytes into a `*compilation*`
   run and the next-error store today. Preferred design — a
   `compilation_feed` object (`begin(label, directory, source)` /
   `bytes()` / `finish(exit_code)`) extracted from compilation's output
   construction, fed by both the ordinary compile child and a failed
   DAP launch, owning CR/ANSI normalization, byte budget, line commits
   and diagnostic hooks, arbitrating with an already-running
   compilation. The payload is `file:line:col:` form and the initial
   directory is `adapter.cwd` (the review confirmed diagnostics are
   cwd-relative). Fallback if the extraction stalls: leave the
   diagnostics in `*dap-output*` and record build navigation as
   deferred — weaker, but better than reaching into compilation
   globals. Tests either way: relative paths with/without `./`,
   multiple diagnostics split across events, an unterminated final
   line, the cap, an active unrelated compilation, and a failed launch
   with no detailed event.
3. **The adapter's working directory is load-bearing**: delve resolves
   `program` and writes `__debug_bin*` relative to *its own* cwd
   (measured: with kg's cwd inherited it built the wrong module).
   `kg_spawn_request.directory` must be plumbed through adapter spawn
   and exposed as `adapter.cwd` in `.kg-dap.json` — distinct from the
   debuggee's `arguments.cwd`, resolved before spawn, required to
   exist, and recorded in the session so launch diagnostics use the
   same value later. delve is the first adapter to need it. The
   built-in's default is `${workspaceRoot}` (least surprising in a
   multi-package module; `program` selects the package), overridable
   per config.
4. **One dlv per session**: no `--accept-multiclient` in dap mode; the
   server exits when a *started* session ends — but **stays alive after
   a failed launch** (measured: reconnect succeeded there), so teardown
   never relies on EOF. Failed-launch cleanup, in order: retain/report
   the structured failure and buffered output; finalize the
   compilation feed; send disconnect if the protocol is usable, without
   waiting forever; close the socket; kill/reap the owned child; clear
   pending callbacks exactly once. Spawn fresh per session. `restart`
   *is* advertised and the spec prefers it over relaunch — bind F11 to
   it for Go only after a real test, and on failure leave the session
   state explicit rather than silently spawning a second dlv beside
   the first.
5. **The optimized-binary trap (`mode:"exec"`)**: against a plain
   `go build` binary the session works but locals are gutted (variables
   missing/unreadable) and delve says so only via the scope name
   `"Locals (warning: optimized function)"`. Surface that name verbatim
   and document `-gcflags="all=-N -l"` in the exec config template;
   `mode:"debug"` passes it automatically.

## `.kg-dap.json` shape

The built-in `delve` adapter spec owns `dlv dap --listen 127.0.0.1:0`,
the announce prefix and the spawn-port mechanics — none of that is the
user's to repeat (an inline adapter object remains the escape hatch for
custom delve installations or flags). In the subplan-01 root schema:

```json
{ "version": 1,
  "configurations": [{
    "name": "Go package",
    "adapter": "delve",
    "request": "launch",
    "arguments": { "mode": "debug", "program": "${fileDir}",
                   "cwd": "${fileDir}", "stopOnEntry": false } }] }
```

`mode:"exec"` variant: `program` is the prebuilt binary, required
absolute after expansion or resolved against `adapter.cwd`
deterministically — documented, with the `-gcflags="all=-N -l"` advice
beside it. `mode` also covers `test` (and `replay`/`core`);
`attach`+`mode:"local"` takes a `processId` — recorded, deferred.
Exception filters are built from the *live* capability set at
configuration time (both of delve's default true), never from a
hardcoded Go list; a capabilities event changing filters mid-run does
not trigger a re-send outside the generic session policy.

## Tests

Fake-adapter modes: launch-after-initialized ordering (shared with
nbcode's mode), `continued` before the step response, duplicate
`terminated`, output-on-child-stderr while the protocol runs on the
socket, build-output-before-failed-launch with the cap exercised,
process-event-before-initialized, restart success and failure,
stale-reference *error* (reported locally, session stays healthy).
Native: the no-hash announce scan — split at every byte, log noise,
CRLF, invalid port, announce-on-stderr asserting a loud failure naming
the expected prefix — child exit before/after announce, connect
refusal, cancel during announce/connect, failed launch followed by
close/reap (no surviving child), and adapter-cwd substitution incl. a
missing directory. A fake spawn-port adapter is required — a stdio fake
with stderr output exercises none of the announce/socket/child
ownership.

Real-adapter smoke needs the harness's `requires_tool` list form
(subplan 01 stage 7) for `dlv` + `go`, and a self-contained Go
workspace planted by `workspace_files:` (no module cache): a
deterministic function + breakpoint line; stdout without newline,
stderr, CRLF and a long line; a scalar and a nested local; a goroutine
that exits before main (one thread exiting is not session death); a
step and a natural completion; and a separate syntax-error fixture for
the compilation-feed path. Adapter cwd is the temporary workspace.
Settle budgets are trivial (fastest adapter), but the cold-build 1.5 s
belongs in the launch allowance, not the settle. Go support lands
without adding Go branches to the generic DAP client.
