## Part 1 — `(quote X)` → `'X` in the writer

The template is the existing `function` block at `fe/fe.c:1090-1097`
(`WriteObject`'s `FeTPair` arm): abbreviate **only** the
single-element proper form, recursively, so the measured Emacs grid
holds —

| Input | Prints |
|---|---|
| `(quote x)` | `'x` |
| `(quote (quote x))` / `''x` | `''x` |
| `(quote x y)` | `(quote x y)` |
| `(quote)` | `(quote)` |
| `(quote . x)` | `(quote . x)` |
| `(a (quote b) c)` | `(a 'b c)` |

Backquote (`quasiquote`/`unquote`/`unquote-splicing`) is **not**
abbreviated (11A Decision 4).  Depth accounting mirrors the `#'`
block's.

Blast radius, enumerated by the audit — these are the *only* expected
textual changes, and finding another means stopping and re-auditing:
`fe/tests/conditions.fe.err:3` and `fe/tests/exhaustion.fe.err:6`
(goldens, regenerated by hand via `fe/test.sh`'s command line — there
is no regeneration target), `fe/test_api.c:2112`.  (kg's two
`test/test_lisp.c:3102-3103` sites are 11D's.)  The deep-trace golden
is unaffected.  fe manifest rows to edit by hand in the same commit
(no XPASS rule on fe's side): `phase7-arity-condition-rendering` —
split it, the quote half now agrees while the `#[...]` byte-code half
stays divergent; `phase7-primitive-quote-arity` — the `-nargs`
workaround note; `primitive-quote-too-many` — drop the now-unjustified
`compare_data: false` opt-out; `writer-bounded-output` family if their
rationales quote a printed form.  `fe/doc/c-api.md:892-894`'s
prin1-compatibility claim becomes true — reword it to say so.
`fe/doc/implementation.md:248-259` (the `#'` writer paragraph) gains
the quote sibling; `fe/doc/language.md:363-388` gains the printing
statement it lacks.

Tests: script-suite case printing the full grid above (golden), plus
`test_api.c` assertions for the dotted/arity edge cases and for
`FeWriteWithOptions` depth interaction.

## Part 2 — `FeTryEvaluateStringWithOptions`

Shape A (11A Decision 5): a sibling of `FeTryCallWithOptions`
(`fe_eval.c:4246-4306`, now in the TU 11B split out) with
`EvaluateInput` in place of `FeCallWithOptions`.  Containment
semantics identical to the protected call: a non-normal completion is
*returned*, not thrown past the frame; the `cleanup_floor` raise, the
`cleanup_catch` null, and the save/restore epilogue all carry over; a
`throw` is contained as the barrier-wall error it is today (the
throw-across-load divergence stays recorded — Shape B is out of
scope).  One audit-flagged detail: `EvaluateInput` writes
`ctx->evaluation_result` without save/restore — the protected variant
must leave the enclosing run's result usable.  Declared in `fe.h`
beside `FeTryCallWithOptions` with the same contract comment shape;
`FE_API_VERSION` 6→**7** in this commit (the language version already
moved in 11B).  `fe/doc/c-api.md`'s "Containing a completion" section
(`:817-851`) documents it beside the call variant.

Tests (`test_api.c`): an error inside evaluated text is returned as a
completion, not thrown; `FeResignal` after containment reaches a
handler established *outside* the protected evaluation (the exact
seam kg's loader will use); a quit and a budget expiry are contained
with their kinds intact; a throw is contained as the wall error;
multi-form strings evaluate forms before the raising one (side-effect
order pinned); GC-stack balance across containment (the
`FeSaveGC`/`FeRestoreGC` pairing survives).
