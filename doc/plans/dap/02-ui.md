# DAP subplan 02 — the debugger UI: panes, layout, keys, REPL

Parent: `doc/plans/2026-08-11-dap.md`; prerequisites: subplan 00 stages
C-F and subplan 01 through stage 6. Everything here is projection —
`dap_ui.c` renders the session/breakpoint tables and owns no protocol
state.

## Special buffers

`*dap-repl*`, `*dap-locals*`, `*dap-output*`, `*dap-stack*`,
`*dap-breakpoints*`, `*dap-threads*`. All written through
`buf_prepare_special_text()` / the edit gateway (which keeps `dap_ui.c`
out of the mutation-gateway census by construction), read-only,
repainted from the tables on one internal "session changed" notification
— start with a single notification point; add granularity only when a
pane measurably needs it (dap-mode's nine hooks are the cautionary
tale). Repaints are debounced (~100 ms, dape's `dape-ui-debounce-time`)
and skipped for panes not currently displayed.

Pane content rules already forced by measurement:

- `*dap-output*`: `stdout`/`stderr` categories, appended **as bytes**
  (debugpy splits one print mid-line across two events), CR/CRLF
  normalized (lldb-dap emits CRLF), rendered like any buffer text —
  adapter output is untrusted and reaches the screen only through
  `display_glyph_at()`. `telemetry` dropped silently; `console` goes to
  the REPL.
- `*dap-stack*`: rendered from the fetched frames (one on stop, 20 when
  this pane paints); frames without an openable source render dimmed and
  non-navigable; the selected frame is marked, hollow-style when it is
  not the top frame (dape's arrow discipline).
- `*dap-locals*`: scopes + variables of the selected frame only;
  expansion state keyed by name-path so it survives re-fetch across
  steps (dape.el:4616-4627). `hover`-context evaluate for values, never
  `repl` (lldb-dap formats those differently, with `$N` side effects).
- `*dap-breakpoints*` and `*dap-threads*` share one logical slot in the
  layout, as GDB does.

One shared `dap-info` major map for all panes: RET dispatches on what
the current line *is* (frame → select+visit, thread → select,
breakpoint → visit, variable → expand/collapse), the
line-kind-as-data idiom (dape's text-property dispatch,
dape.el:1367-1385) rather than one map per pane — also thrifty with the
keymap table. `d` deletes a breakpoint, `D` toggles enable, `q` buries.
The read-only-buffer mode-map predicate leak the LSP plan fixed
(kbd.c's `key_update_mode_maps()`) must not re-appear: `*dap-*` buffers
get their map by name, not by "read-only and not dired".

## Layout

Target arrangement (Emacs gdb-many-windows', adapted):

```
+---------------------------+---------------------------+
| *dap-repl*                | *dap-locals*              |
+---------------------------+---------------------------+
| source                    | *dap-output*              |
+---------------------------+---------------------------+
| *dap-stack*               | *dap-breakpoints*/threads |
+---------------------------+---------------------------+
```

Built in one `win_arrange_grid()` call (subplan 00-E) — never six
chained `win_display_buffer_other_window()` calls. Equal column widths
are the accepted v1 limitation; a weighted reflow is a recorded
follow-on. `F12` (`dap-many-windows`) toggles: entering saves the user's
configuration (`win_configuration_save()`), leaving — or the session
dying — restores it. Session end always restores; a dead buffer in the
saved config falls back per subplan 00-E's rule. The layout preference
persists for the session lifetime, not per toggle-flip.

Source-line behavior on stop: visit the frame's file (the existing
shared `editor_visit_file_position()` seam the LSP xref work extracted),
`KG_DECOR_FACE_DEBUG_CURRENT` on the stopped line, cursor to column 0
(DAP columns are not byte offsets — v1 ignores them). Never steal the
window when the user is in a `*dap-*` pane (dape's focus discipline).

## Keybindings

The `dap` minor map (created at startup, subplan 00-D) is active exactly
while a session exists. Default table (parent plan, decision 1 —
gud-style):

```
F4    dap-evaluate            C-F5   dap-step-instruction (cap-gated)
F5    dap-step-in             F6     dap-next
F7    dap-step-out            F8     dap-continue
F9    dap-breakpoint-toggle   C-F9   dap-breakpoint-temporary
F10   dap-until               M-F10  dap-goto (cap-gated)
F11   dap-restart             M-F11  dap-terminate
F12   dap-many-windows        M-up / M-down   dap-frame-up / -down
PageUp/PageDown also frame-up/-down while a session is live.
```

`dap-until` is a temporary breakpoint + continue (the portable
gud-until); `dap-goto` is capability-gated (debugpy yes, lldb-dap no —
the refusal names the adapter); `dap-restart` is client-side relaunch.

Every capability-gated command that cannot run says *why* ("lldb-dap
does not support goto") — never a silent approximation.

Customization story, documented in README + doc/lisp-api.md: the map
pre-exists in C, so `(define-key 'dap-mode-map "<f5>" 'dap-step-in)`
works from init.el once subplan 00-C lands; `keymap_find()`'s
`-mode-map` aliasing already resolves the name. `global-set-key` stays
C-c-only by design — F-keys are reachable through define-key precisely
because the dap map is a real native map.

Documentation path: all keys and commands in `doc/kg.1` and README.
`src/help.c` is *not* extended unless `utils/check_help_drift.py` is
taught to read the dap map's bindings in the same commit — the script
currently requires help-table keys to be bound in kbd.c's tables and
would fail otherwise.

## REPL

v1 `*dap-repl*` is deliberately small: a prompt line, history,
`evaluate` with `context:"repl"`, output interleaved (console category
lands here). Completions (`supportsCompletionsRequest` — both adapters
have it) and variable commands are follow-ons. A failed evaluate prints
its error in place; it is never a session error.

## PTY acceptance

tmux-backed cases asserting the visible story: breakpoint decoration
appears on F9-equivalent; stop highlights the line and populates
`*dap-stack*` (`expected_screen_contains` on a frame name) and
`*dap-locals*` (a known variable=value); step advances the highlight;
F12 paints six panes; F12 again restores the prior layout; session death
restores the layout and deactivates the map (a debugger key then
self-inserts or beeps — assert one). Settle floors sized for the
sanitizer lanes; the fake adapter drives all of these, real-adapter
smoke stays in subplan 01 stage 7.
